Simulate Transaction Abort & ROLLBACK

Executes a stock reduction inside a transaction block, simulates an unexpected error or inventory check failure, and fires a ROLLBACK. Verifies that no partial updates corrupt the database.

BEGIN;
UPDATE inventory SET stock_quantity = stock_quantity - 10 WHERE product_id = 2;
RAISE EXCEPTION 'Simulated Failure';

Theoretical & Practical Takeaway (Table 4.1 in Case Study Report):

Even though a B-Tree index (idx_order_items_product_id) exists on the table, PostgreSQL's cost optimizer intentionally selects a Sequential Scan. Because the table contains only 10 rows (residing inside a single 8KB disk page), scanning the block directly incurs an estimated cost of only 1.12, compared to 8.19 for an Index Scan which requires navigating B-Tree blocks and issuing random heap page reads.

Database Architecture & Relational Entities

Normalized schema structure enforcing 1NF, 2NF, and 3NF across 6 relational tables.

customers (5 rows)

  • customer_id SERIAL PK
  • customer_name VARCHAR(100)
  • email VARCHAR(100) UNIQUE
  • phone VARCHAR(20)
  • city VARCHAR(50)

products (6 rows)

  • product_id SERIAL PK
  • product_name VARCHAR(120)
  • category VARCHAR(60)
  • price NUMERIC(10,2)

inventory (6 rows)

  • inventory_id SERIAL PK
  • product_id INT FK,UK
  • stock_quantity INT
  • last_updated TIMESTAMP (Trigger)

orders (6 rows)

  • order_id SERIAL PK
  • customer_id INT FK
  • order_date DATE
  • status VARCHAR(20)

order_items (10 rows)

  • order_item_id SERIAL PK
  • order_id INT FK
  • product_id INT FK
  • quantity INT
  • unit_price NUMERIC(10,2)

payments (6 rows)

  • payment_id SERIAL PK
  • order_id INT FK
  • amount NUMERIC(10,2)
  • payment_method VARCHAR(30)
  • payment_status VARCHAR(20)
  • payment_date TIMESTAMP
